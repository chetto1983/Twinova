## What runs

- **The PLC's online change** (`engine`: `Controller::reload`, `line_bind.rs`, `Engine::change_program`):
  - a program saved outside Twinova replaces the running one between two milliseconds, through truST's warm restart;
  - the process image is carried over;
  - the line binds its addresses again;
  - the change is an input of the replay.
- **The files for the LSP** (`lsp_files.rs`): `trust-lsp.toml`, once, and `.twinova/lsp/field.st`. Both are written at
  open, save and Build.
- **The watch** (`watch.rs`):
  - a `notify` watcher on the project's folder;
  - 250 ms of quiet, then the listed sources are read again;
  - those that differ go to the webview as `disk-sources`.
- **The webview** (`sources.ts`, `App.svelte`, `Editor.svelte`):
  - a program goes online, a behaviour rebuilds;
  - a file edited here and changed on disk is held;
  - an edited tab is marked and can be reverted.
- **CI:** a pull request labelled `installer` builds the MSI and keeps it 14 days.

## Found by measuring

- **truST's reload is a warm restart.** `count` went from 50 to 0, RETAIN kept 50, a running TON's `ET` went from
  490 ms to 0, and the time and the scans went on.
- **The reload starts from an empty process image.** The field would read every output as 0 until the first scan.
  `write_io` accepts `%Q` inside the image the new program admits (past it: "address exceeds admitted process image"),
  so both images are copied over.
- **A dropped input.** An input the new program does not declare would keep its last value. It is cleared.
- **A latched output that is not RETAIN drops** at the first scan: the demo's motor, and so its belt. Declared RETAIN,
  it runs on. These are the warm restart's semantics.
- **Opening a fixture in place** wrote the LSP files into the repository and broke the corpus, which checks that a
  fixture holds only its project's files. The tests open copies (`test_fixtures::copied`), and so does the E2E
  (`fixtureCopy`).
- **`notify` reports reads on Linux,** Twinova's own reading of the sources included. Without filtering them, every
  quiet period would wake the watch again.
- **The webview's notices.** Opening dropped the project's notice, and Save's notice replaced it. Both are shown now.
- **The backend mock** in `snapshot.test.ts` lacked `onDiskSources`. Every test passed, but vitest reported 2 errors
  and Stryker's dry run failed.
- **The first LSP probe.** It answered the server's requests only at the end, which held the indexing back; a
  corrected client measured the rest.

## What this does not prove

- **A change that keeps every value.** truST's online change is a warm restart.
- **VS Code's own save on Linux.** The E2E writes the files in the two ways editors save. VS Code itself is the
  user's test on Windows.
- **Other trust-lsp versions,** and the false E202 errors in the blocks, which remain.
- **Folders on network drives, and macOS.**
- **A partly written file applied before the end of its write.** A burst is read 250 ms after its last event; a
  write slower than that could be read half-done, refused at compile, and read again whole at its last event.
