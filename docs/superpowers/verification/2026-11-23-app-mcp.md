# Verification: the open app driven over MCP, and a release one can use (ROADMAP 2.8)

Date: 2026-11-23. Spec `2026-11-23-app-mcp-design.md`, plan `2026-11-23-app-mcp.md`, pull request #55, release v0.3.0.

## What was measured

- **The control channel** (`twinova-control`, 9 tests over the loopback):
  - a client with the launch's token is answered in order, and a wrong or missing token is refused and closed;
  - a busy port is skipped;
  - each request has an id of its own, and an answer to another request is refused;
  - the file is its user's only (mode 0600).
  - The app side (`control_tests.rs`, and `tests/control_start.rs` in a data folder of its own) checks four things:
    a request reaches the window and its answer comes back; one the window does not answer in 60 s fails; requests
    wait for the window to be ready; the channel opens in the app's data folder and lets the token in.
- **The agent attached** (`agent/tests/attached.rs`): an rmcp client drives the agent, the agent drives a stand-in
  app over the real channel, and `batch` undoes the edits of a batch that fails. The built binary with no argument
  finds the app through its file and serves it on stdio.
- **The registry** (vitest 301/301): every command of the main window, the PLC pane and the dock is run against a
  stubbed backend; a parameter the schema does not name, or a missing required one, is refused by name.
- **E2E on Linux, the real app** (`e2e/mcp.mjs`, 22/22, under Xvfb):
  - the debug app is driven by `twinova-agent`, attached through the discovery file;
  - the client is the TypeScript SDK's (1.32.2), a second implementation beside rmcp's;
  - all 40 commands of the registry are run, and the run fails if one is not;
  - after each, WebDriver reads the window: the project and the tree, undo and redo, a batch rolled back, Build, the
    PLC tab, the Ladder drawing, the table's forced and written values, the line's time, a HOLD and its steps, an
    edited source, theme and language, the archive and the folder;
  - a Ladder file shows no breakpoint margin and its breakpoints are refused;
  - the screenshot is a PNG of the window's size, 1440 × 900 ([picture](img/2026-11-23-mcp-screenshot.png));
  - the headless agent answers the same client.
  - Regressions on the same build: `breakpoints.mjs` 15/15, `ladder.mjs` 6/6.
- **Found by the measures and fixed:**
  - the agent's answers that were not JSON objects (lists, strings, null) went out as structured content; the
    TypeScript SDK refused them ("expected record, received array"), and rmcp's own client never had;
  - `step` with `ms` ran one scan and said nothing;
  - `values` asked right after `monitoring` answered every value null;
  - a breakpoint in a Ladder file held the line at the lowered ST's line 52, in a file of 42 lines.
- **The packages,** CI's bundle jobs on 593af87:
  - the deb (12.54 MiB) lists `usr/bin/twinova` and `usr/bin/twinova-agent`, and the AppImage (86.80 MiB) carries the
    agent too; the agent taken out of each answers the SDK's client (30 tools, an example opened);
  - the MSI (12.83 MiB), unpacked by an administrative install, has `PFiles\Twinova\twinova.exe` and
    `twinova-agent.exe` side by side, and that agent answers too.
- **`twinova-agent setup`** with the real `claude` CLI in a scratch home: `claude mcp get twinova` answered
  "Connected". Claude Desktop's file was written beside a server already there, and the file is left as it is when it
  is not a configuration (`setup_tests.rs`).
- **Mutation:** the first complete run on this pull request (593af87) left eleven survivors. Each was reproduced by
  hand, then killed by a test or put out of scope with its reason (`.cargo/mutants.toml`): the window's picture on
  WebKit and WebView2 needs a real window, and the second needs a Windows build.
- **Windows:** `e2e/mcp.mjs` runs on windows-2022 in CI's `e2e` job: the app driven through every command, and the
  picture taken by WebView2's `CapturePreview`. The pull request is merged only with that job green on its last
  commit.

## What this does not prove

- That an MCP client other than rmcp's and the TypeScript SDK's reads the answers; both follow the 2025-06-18
  schema.
- That Claude Desktop reads the file `setup` writes: it was not run here, and on Linux it is not an official build.
- That the picture is right on a scaled display. It was measured at a device pixel ratio of 1, on Xvfb and on the
  runner.
- That the PLC pane's commands reach the pane once it is in its own window: the channel speaks to the main window
  only, as the spec says.
- That two apps open at once can each be reached: the file names the last one started.
