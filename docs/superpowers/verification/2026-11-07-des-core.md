# Verification: the discrete-event core spike (2026-11-07)

Spec: `docs/superpowers/specs/2026-11-07-des-core-design.md` (ROADMAP 3.1). Prototype: `prototypes/des-probe`, run
with `cargo run --release` on a 4-core cloud container, Rust 1.99.0, nexosim 1.0.0. The executor patch was also run
against nexosim `main` `0579f95`.

## Acceptance: "decision recorded with measurements"

| What | Result |
|---|---|
| Order of simultaneous events, nexosim 1.0 | stable per thread count, reversed with 1 thread (7..0) against 2+ threads (0..7) |
| Same, with the FIFO executor patch | 0..7 for 1, 2, 3, 4 and 8 threads; 20/20 runs, also with skewed work |
| nexosim's suite with the patch | 220 passed before and after; the new ordering test fails on the old executor |
| Throughput cost of the patch | one thread, a message per event: 10–15 % slower; other cases within noise |
| Save and restore | exact, 210-byte state (models only, not `Model::Env`) |
| The M1 scene on nexosim, 60 s, outlet free and blocked | identical to M1's engine for 6 000 scans, controller and scene |
| Negative control (photocell one scan late) | detected with the outlet blocked, not with it free |

Decision (user, 2026-11-07): nexosim, on one thread, with the executor patch, proposed upstream.

## What this does not prove

- That the patch is accepted upstream: the PR is not open yet (it needs the user's fork).
- Miri on the patch: not run, as no nightly toolchain is installed.
- PLC state in snapshots: `Model::Env` is not saved, so 3.5 must address it.
- Scenes richer than M1, and the order of more than one PLC or scene model at one instant beyond the probe's
  synthetic case.
