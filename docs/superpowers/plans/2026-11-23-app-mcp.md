# Plan: the open app driven over MCP, with screenshots, and a release one can use (ROADMAP 2.8)

## Goal

An agent drives the Twinova window a person has open, sees it through screenshots, and reaches every feature of the app
over MCP; the release installs the agent beside the app, with example lines and a guide.

## Architecture

After SolidCraft's design (spec, the user's choice of 2026-11-23):
- **The control channel** (`src-tauri/src/control*.rs`): loopback TCP, JSON lines, a token per launch in
  `control/current.json`, readable by its user only. A request becomes an event to the main webview; its answer comes
  back through the `control_reply` command; `screenshot` is answered in Rust.
- **The command registry** (`src/lib/control/`): every action of the window, each with a name, a sentence, a JSON
  Schema and the function the window's own button calls.
- **`twinova-agent`**: attaches to the open app through the channel and serves `list_commands`, `describe_command`,
  `execute`, `batch`, `screenshot`, `state`; without the app, the headless session as today. `setup` writes the MCP
  clients' configurations.
- **The release** installs the agent beside the app and the example lines are in the binaries.

## Tech Stack

Rust (rmcp 3.9.0, tokio), Tauri 2.12.5 (`with_webview`, events), webkit2gtk 2.0.2 with cairo-rs 0.18.5 (`png`),
webview2-com 0.39.1, Svelte 5.

## Spec

`docs/superpowers/specs/2026-11-23-app-mcp-design.md`, from the user's direction of 2026-11-23 ("L'MCP deve pilotare
l'app aperta, vai con tutto e fare gli screenshot").

## Global Constraints

- One registry: an action is the same code from a button and from the channel.
- Every command is reached by an end-to-end test through a real MCP client and the running app, checked in the window.
- Files under 600 lines; coverage at least 85 %; mutation with no survivor.
- Loopback only, a token per launch; the channel can be turned off.

## Review Focus

- The window follows every tool that changes something (decision 3): no tool leaves it stale.
- A tab with edits of its own is never overwritten by an agent's write without its notice.
- The screenshot is the window as drawn, on both platforms.

## Decisions taken while writing this plan

1. The request travels to the webview as an event and back as a command, with an id and a timeout (60 s, as
   SolidCraft's), so a command that waits for the engine (Build) answers when the window's action has finished.
2. The channel runs on Tauri's tokio runtime, one task per connection, started in `setup`.
3. The headless agent keeps its tools: the registry lives in the webview, which a headless session has not.
