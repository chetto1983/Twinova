# Plan: the Run loop's pace and the drive feedback as a native model (ROADMAP 4.4b1)

## Goal

As fast as possible uses its whole frame, and a conveyor's `velocity`, `encoder` and `pulse` come from its native
model, so a simulated millisecond costs about a fifth less.

## Architecture

- **`commands.rs`:** the Run loop sleeps the frame less what the tick took.
- **`drive.rs` (new):** OIP's `publishDrive` in Rust, the velocity and the pulse of one conveyor.
- **`field.rs`, `field_image.rs`:** the signals a family's native model writes are not the block's: not placed, not
  copied.
- **`line.rs`:** after the physics step, each conveyor's bound feedback is written to the controller, with the sensors
  and the sinks.
- **`twinova-physics`:** the world gives a conveyor's speed as last set.
- **Fixtures:** the drive block without the three signals, by an independent script.

## Global Constraints

- The physics fingerprints do not change.
- Fixtures are written by an independent script.
- Gates: 600 LOC, coverage ≥ 85 %, no surviving mutant on the changed code.
- A test that fails is reported before it is edited. The 4.4b tests that read the three signals from the block move
  to the native model with the same figures: that move is the approved change.

## Review Focus

- A bound native signal must not also be copied from the field's image, which would overwrite it with zero.
- The pulse's remainder across pitches, and a reversed surface.
- The loop's sleep when a tick overruns its frame.

## Decisions taken while writing this plan

- **The feedback reads the world's speed and travel after the step,** so it describes the millisecond just simulated.
- **The pulse's travel is kept by the line,** per conveyor, in f64.
