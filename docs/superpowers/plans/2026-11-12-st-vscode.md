# Plan: ST in VS Code (ROADMAP 4.6)

## Goal

**Saving in VS Code reaches the running scene:**
- a `.st` file saved in VS Code, in a project folder Twinova has open, reaches the running scene;
- the line program is changed online, and the plant keeps running;
- a behaviour rebuilds the scene at time zero.

**VS Code with truST's Marketplace extension reads the folder:**
- with no false errors in the program;
- with only the documented E202 errors in the blocks.

**The acceptance:** the user, on a Windows virtual machine, from an MSI that CI builds for the pull request.

## Architecture

- **`twinova-engine`.**
  - `Controller::reload` wraps truST's `reload_sources`.
  - `Line` binds the PLC's addresses in one function, shared by Build and the online change.
  - `Engine::change_program` records the change as an input. A snapshot keeps the program its engine was built with.
  - `field.rs` gives the generated `PROGRAM Field` and configuration on their own.
- **The app.**
  - `src/watch.rs`: a `notify` watcher on the open folder that emits `disk-sources` with the texts that differ from the
    project's.
  - `src/lsp_files.rs`: writes `trust-lsp.toml` and `.twinova/lsp/field.st`.
  - A `change_program` command.
- **The webview decides** (decision 6 needs the editor's state, decision 1 of this plan):
  - with unbuilt edits in a changed file, it shows a notice;
  - otherwise it calls `change_program`, or `build` for a behaviour, and runs again if it was running.
- **CI.** `ci.yml`'s `bundle` job also runs for a pull request labelled `installer`, and uploads its MSI as an artifact.

## Tech Stack

- Rust 2024: `twinova-engine` and the app, with truST pinned at `6405915` and `notify` 8.2.1.
- Tauri 2, Svelte 5.
- truST's VS Code extension 0.38.0, from the Marketplace.

## Global Constraints

- **The plant is never touched by an online change:** the world, the field, products and devices.
- **The replay is deterministic through a change.** The fingerprint tests stay green, and a new one goes through a
  change.
- **Nothing typed is lost.** Unbuilt edits hold a disk change.
- **Twinova writes nothing the user did not ask for into the manifest.** The LSP's two files are outside it.
- **Files:** none over 600 lines.
- **Tests:** no sleeps as synchronisation. The watcher's tests wait on its channel with a deadline.
- **Gates:**
  - fmt, clippy;
  - coverage ≥ 85 %;
  - cargo mutants with no survivor on the engine's change, the line's binding and the watcher's filter;
  - Stryker ≥ 70 % on `sources.ts`;
  - svelte-check, oxlint, knip, jscpd, i18n;
  - the E2E on Linux and windows-2022.

## Review Focus

- **The line's binding.** After a change, Build's and the change's bindings must give the same ports for the same
  program.
- **The order of inputs.** A change between two steps at the same time as a press: the order is the recorded one.
- **The watcher.**
  - It only reacts to manifest-listed sources whose text differs.
  - A half-written file is retried, not applied.
- **The `installer` label** builds an unsigned MSI, kept 14 days. No tag and no release.

## Decisions taken while writing this plan

1. **The webview applies a disk change.** The spec's decision 6 depends on the editor's unbuilt edits, which only the
   webview knows. Rust watches, compares, and emits `disk-sources` (`{ program, behaviours, kind }`). The webview
   applies it through `change_program` or `build`, the same commands a click uses.
2. **`notify = "=8.2.1"`** becomes a direct dependency of the app. It is already locked through trust-runtime, so no new
   crate enters the tree.
3. **The MSI for the user's test.**
   - `ci.yml`'s `bundle` job runs on pushes to `main` and, from now on, on a pull request labelled `installer`. It
     uploads `twinova-msi` (14 days).
   - `release.yml` is not used: it creates a tag and a public release.
   - The MSI is unsigned, so SmartScreen asks once. If WebView2 is missing, the installer downloads it (Tauri's default,
     `tauri-utils` 2.10.2 `config.rs:1001`), so the VM needs internet or WebView2 already installed (Windows 11 has it).
4. **The change is an input `Program(Vec<(path, text)>)`.**
   - `Saved` gains `program`, the sources the engine was built with.
   - `restore` builds from them, then replays.
5. **`field::config_source(project)`** returns the `PROGRAM Field` and `CONFIGURATION Twinova` text. `generate` puts the
   blocks before it, as today.
6. **Where the LSP's cache goes is measured first in Task 3.**
   - If `[indexing] cache_dir = ".twinova/lsp-cache"` keeps it out of the project's files on 0.24.75 and 0.38.0, the
     generated toml sets it.
   - If not, the toml leaves it, and the verification says where it is.
