# Plan: U1, remove the noise (ROADMAP M4b)

## Goal

Every shipped example opens with zero problems at the default level, each fact appears once on screen, no section is
drawn empty, components are named as a person names them, language and theme leave the main bar, and the Linux
packages start on Ubuntu 22.04.

## Architecture

- **Problems:** truST's analyzer (`analysis.rs`) loses the false W009; the webview (`analysis.ts`, `WorkspaceDock`)
  treats style codes as hints.
- **The rest is the Svelte shell:** `App.svelte`, `StatusBar`, `SceneTree`, `Inspector`, `Catalogue`, `Toolbar`,
  `WorkspaceDock`, `IoPanel`.
- **Packaging** is CI's bundle job and `release.yml`.

## Tech Stack

Rust (`twinova` app crate), Svelte 5 + TypeScript, Paraglide messages, Vitest, WebdriverIO E2E under Xvfb, GitHub
Actions.

## Spec

`docs/superpowers/specs/2026-11-26-ux-consolidation-design.md`: decisions 7 and 8 (part), acceptance A3, phase U1.

## Global Constraints

- No file above 600 lines; `App.svelte` is at 594 and must not grow.
- Gate 2 after each task:
  - Rust: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`,
    `cargo test -p twinova <filter>`.
  - TypeScript: `npm run check`, `lint`, `format:check`, `check:i18n`, `deadcode`, `dup`, the changed Vitest files,
    `npm run build`.
  - The real app's E2E for what changed.
- Coverage of 85 % and mutation run in CI on the pull request. Every new message exists in `en.json` and `it.json`.
- The MCP commands `language` and `theme` keep working, so agents see no change.

## Review Focus

- W009 is dropped only where it names a PROGRAM. truST's runtime runs every program each cycle, either in a task or
  as a background program: `trust-runtime` at `6405915`, `runtime/cycle.rs:238` `execute_background_programs`.
  A function or block that nothing calls keeps its W009.
- The badge counts errors, not hints. A hidden hint must still be one click away.
- The CI change must not restore a Rust cache built on 24.04 into a 22.04 job: build scripts linked against a newer
  glibc would not start.

## Decisions taken while writing this plan

1. **W009:** dropped when the text before its span ends with the keyword `PROGRAM`. That span is the program's name in
   its declaration (`analysis_tests.rs:49`, `11:9`).
2. **Hints:** W001 (unused variable) and W008 (cyclomatic complexity). Monaco shows them as hint markers. The list hides
   them by default behind a "Show N hints" toggle. The badge counts the analysis' errors plus the build's error.
3. **Scene name:** once, in the project button. The viewport's header row goes, and the tree's root row becomes the
   panel's heading "Components" with the count.
4. **Modified marker:** a dot on the project button. It leaves the status bar and the viewport header.
5. **Status bar:** run state or HOLD, virtual time, notice, error, build state. The object count and
   "truST · IEC 61131-3" go.
6. **Inspector with nothing selected:** the hint only. The scene's step and scan get a home in U6, with the contexts.
7. **Operator section:** drawn only when the project has panel buttons. The task-cycle line says "Run the line to
   measure the scan" instead of dashes.
8. **Family names:** translated, one message per family (15), used by the tree, the Inspector's header and the
   catalogue. No version and no "Twinova · v1".
9. **Settings:** a gear button opens a popover with Language and Theme. The light default is U7's.
10. **Packaging:**
    - Linux bundles and the Linux agent build on `ubuntu-22.04`, in `ci.yml`'s bundle job and in `release.yml`.
    - The Rust cache's shared key names the runner image.
    - A CI step fails if the app or the agent needs a glibc above 2.35.
    - Verified on the pull request with the `installer` label.
